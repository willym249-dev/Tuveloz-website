# Notes for AI contributors

More than one AI works on this repository. These are the things worth knowing
before you change anything.

## Read first

1. [`PROJECT_STATUS.md`](PROJECT_STATUS.md) — what is built, what is verified,
   what is deliberately unfinished.
2. [`docs/decisions/`](docs/decisions/) — decisions already made, and why.
3. [`docs/CONTRIBUTING.md`](docs/CONTRIBUTING.md) — conventions.

## Hard rules

- **Never commit to `main`.** Branch, then open a PR.
- **Run `npm run verify` before committing.** Typecheck, lint and format check.
- **Do not rewrite working features** without a stated reason. If a decision in
  `docs/decisions/` looks wrong, write a new ADR that supersedes it rather than
  quietly reversing it.
- **Do not delete existing work** unless it is genuinely obsolete — and say so
  in the commit message.
- **Update `PROJECT_STATUS.md`** when a major feature lands.

## Boundaries that matter

- Screens (`src/app`) hold view state only. Logic goes in
  `src/features/<feature>`.
- Dependencies point one way: routes → features → lib. Never the reverse.
- No `supabase.from(...)` in a screen — use a repository.
- No `firebase/*` imports in a screen — use `src/lib/firebase/auth.ts`.
- No hex values or font sizes in components — use tokens and utility classes.
- Every new table gets RLS **and** its policies in the same migration.

## Traps that have already been hit

- `src/types/database.ts` uses **type aliases, not interfaces**. Interfaces do
  not get implicit index signatures, which makes supabase-js silently infer
  `never` for every query result. It compiles; it just stops working.
- `supabase.auth.*` throws. Identity is Firebase's job. See ADR 0004.
- Expo Router's typed routes are generated by `expo start` into `.expo/types`.
  A fresh clone typechecks with looser href types until the dev server has run
  once.
- `getReactNativePersistence` exists only in Firebase's React Native build.
  `src/types/firebase-auth-react-native.d.ts` declares it so the call site
  stays typed.

## Report honestly

If something is untested, say it is untested. `PROJECT_STATUS.md` separates
"verified" from "not yet verified" for exactly this reason — keep that
distinction accurate.
